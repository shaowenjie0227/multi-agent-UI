# 多 Agent 协同工作流 + 实时可视化监控面板

## 总体

- **backend/**：Python 3.10+ FastAPI（venv），REST + WebSocket，事件落盘
- **frontend/**：React 18 + Vite + TS + Tailwind + React Flow，深色实时监控面板
- `./dev.sh` 一键并行启动（uvicorn :3001 + Vite :5173）

## 配置型设计：供应商 → 模型 → Agent

```
Provider 供应商: {id, 名称, baseUrl, apiKey, 启用}          ← 供应商管理界面统一添加
Model 模型:     {id, 供应商id, 模型名(如 grok-4.7), 备注}   ← 挂供应商下，手动加或一键拉取
Agent:         {id, 名称, 角色人设prompt, 绑定(供应商+模型 | Mock), 启用} ← Agent 管理界面配置
```

- 全走 OpenAI 兼容协议（openai SDK base_url 覆盖），一个适配层通吃所有供应商；可混搭不同 agent 用不同模型
- 存 `data/providers.json`、`data/agents.json`，改完即生效

## 工作流

### 阶段一 · 交互式需求分析（人机对话闭环）

1. 用户提交需求 → 需求分析师产出**初版方案 + 边界问题列表**
2. 运行暂停（waiting_user），界面需求对话面板激活：方案全文 + 问题清单 + 对话输入框
3. 用户回答/提修改意见 → 分析师给出**修正版方案**（仍有不明确处继续追问），可多轮
4. 需求清晰后分析师给出**完整方案**，界面弹确认门：〔满意，进入开发〕/〔不满意，继续修改〕
5. 不满意 → 继续对话修改（回到 3）；满意 → 锁定最终版需求方案，进入阶段二

### 阶段二 · 开发落地 ⇄ 需求测试（带方案返工闭环）

- **首轮开发**：开发工程师依据最终需求方案产出技术实现
- **需求测试**：测试工程师对照需求规格与验收标准产出测试用例 + 测试报告，结论 通过/不通过
- **返工轮（核心闭环）**：不通过时，开发工程师收到的上下文 = **最终需求方案 + 本轮已有实现 + 测试报告失败项清单**，据此继续开发、输出修订版实现 → 再次提交测试 → 直到测试通过，或达返工轮次上限（默认 2，超出后带遗留问题汇总交付）
- **交付**：编排者汇总 = 最终需求方案 + 最终实现 + 测试报告

**内置角色**（种子数据，界面可增删改）：编排者、需求分析师（交互式）、开发工程师、测试工程师。

## 后端结构

```
backend/app/
├── main.py / store.py / schemas.py   # REST + /ws + JSON 存储
├── engine/
│   ├── orchestrator.py               # 计划生成、返工轮决策与上下文组装、汇总
│   ├── analyst_loop.py               # 需求对话循环：asyncio.Queue 等待用户输入 ↔ 分析师响应
│   ├── executor.py                   # DAG 拓扑调度，asyncio 并行，依赖产出注入
│   └── bus.py                        # 事件总线 → WS 广播 + runs/<runId>.json 落盘
└── providers/  openai_compat.py + mock.py
```

- REST：`/api/providers`(CRUD)、`/api/providers/{id}/models`(CRUD+拉取模型列表)、`/api/agents`(CRUD)、`/api/runs`(启动/停止/历史/事件回放)、`POST /api/runs/{id}/input`(用户对话/确认)
- 运行状态机：`analyzing ⇄ waiting_user → approved → executing(开发⇄测试返工循环) → completed/failed`

## 事件模型（可视化数据源）

带 runId/seq/timestamp/agentId/taskId/round：`run.started/completed/failed`、`proposal.updated/final`（方案版本流）、`questions.ready`、`user.input`、`approval.requested/granted/rejected`、`plan.created`、`agent.status`（thinking/working/waiting_user/done/error）、`agent.message`、`handoff`（含返工交接：测试→开发带报告）、`task.started/completed`、`review.verdict`（测试结论+失败项）、`result.final`。前端状态 = 纯函数事件重放。

## 前端布局（深色监控面板）

- 顶栏：任务输入 + 开始/停止 + 供应商管理 / Agent 管理入口
- 中部左（主区）：FlowGraph 拓扑图 —— 节点=子任务（角色徽章+轮次标记），边=依赖 + **测试→开发返工回环线**（红色虚线），状态着色（灰→黄→绿→红；分析师对话期显示等待呼吸灯），编排者置顶
- 中部右：**需求对话面板**（阶段一主显：方案版本流+问题清单+对话输入+确认门）；阶段二切换为 Agent 卡片（状态/当前任务/各轮产出摘要，返工轮可展开看测试失败项）
- 底部：实时消息流（返工交接消息高亮）；完成后交付物 markdown 渲染（方案+实现+测试报告分节）

## 实施步骤

1. 脚手架：Vite+Tailwind 前端、FastAPI 后端（venv）、dev.sh
2. schemas + store + 供应商/模型/Agent 管理 REST
3. openai_compat + mock provider → 引擎（bus / analyst_loop / orchestrator 含返工上下文组装 / executor）→ WS
4. 前端：socket + 事件重放 + 配置对话框 + 监控组件 + 需求对话面板（确认门）
5. Mock 全流程端到端：需求对话→确认→开发→测试不通过→带方案返工→复测通过→汇总；再验真实供应商 key 通路
6. 浏览器自动化实测：对话暂停/恢复、确认门、返工回环与轮次标记、消息流、结果渲染、配置生效；打磨

## 说明

- 调真实模型需自备各供应商 API key（ZCode 客户端内订阅无法被外部程序调用）；Mock 模式无 key 完整可用，对话框随便输入即可推进演示
- 阶段一对话轮次用户主导不设上限；阶段二返工轮默认上限 2（防死循环），超限带遗留问题收尾
