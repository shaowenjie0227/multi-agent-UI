# 模型筛选 Agent —— 集成进 multi-agent UI

## 目标
在现有工作台新增「模型推荐」功能：用户粘贴任务描述 → 返回首选模型 + 推理档位 + 理由 + 备选方案；机制为「内置模型知识库 + LLM 匹配，无可用 API 时自动降级为规则匹配」。所有代码写入 `multi-agent UI` 项目（`llm selector/` 空目录不再使用）。

## 一、后端

### 1. 模型知识库 `backend/data/model_knowledge.json`（新建，用户可自行编辑）
约 14 个主流模型档案，每个条目字段：`id / name / vendor / strengths(任务维度) / weaknesses / contextWindow / reasoningLevels(支持的推理档位) / speedTier / costTier / bestFor(一句话中文点评)`。

收录：cc-opus5-5、gpt-6.1-sol、gpt-6.1-mini、grok-4.7、grok-4、ds4.1、deepseek-chat、deepseek-reasoner、glm-4.7、glm-4.6、gemini-3-pro、qwen-max、kimi-k2.5 等（如个别命名与你想用的不符，改 JSON 即可，不改代码）。

任务维度统一词表（规则引擎与 LLM 输出共用）：coding / debugging / refactoring / agent_tool_use / math_reasoning / long_context / writing_creative / writing_business / translation / summarization / qa_knowledge / data_analysis / multimodal / speed_sensitive / cost_sensitive 等。

### 2. 推荐引擎 `backend/app/selector.py`（新建）
- `load_knowledge()`：读 JSON，带缺省容错。
- `classify_rules(task)`：中英文关键词启发式，输出任务维度标签。
- `score_rules(tags, prefs)`：对知识库每个模型按维度匹配打分（强项加分、弱项扣分，成本/速度偏好加权），返回排序结果，top1/top2 差距决定置信度。
- `recommend_llm(task, prefs, kb_digest)`：取第一个启用且有 apiKey 的 Provider，直接调 `real_chat()`（复用 `providers/openai_compat.py`），系统提示词内嵌知识库摘要，要求输出严格 JSON（tags + primary + alternatives + reasoningEffort + rationale + confidence），用现成的 `parse_json_tolerant()` 解析。
- `recommend()` 主流程：先试 LLM，校验其输出的 modelId 必须在知识库内、reasoningEffort 必须在该模型支持的档位内（否则钳制/剔除、用规则结果补位）；任何失败（无可用 Provider、超时、解析失败）都静默降级为规则路径，并在返回里标注 `engine: "llm" | "rules"`。

### 3. API（`schemas.py` 追加模型，`main.py` 追加路由）
- `POST /api/recommend-model`：body `{task, prefer: {cost: "low"|"balanced"|"quality", speed: bool}}` → 返回 `{engine, tags, primary: {modelId, name, vendor, reasoningEffort, rationale, confidence, inWorkspace, providerId?, providerModelId?}, alternatives: [...]}`。`inWorkspace` 通过模型名与 providers.json 现有模型归一化匹配得出。
- `GET /api/selector/models`：返回知识库全量（供前端「查看模型库」页签展示）。

### 4. 推理档位落地（小改动，让推荐结果可执行）
- `schemas.py` Agent 增加可选字段 `effort`（"default"|"off"|"low"|"medium"|"high"，默认 "default" 不下发）。
- `providers/openai_compat.py` `real_chat()` 增加 `effort` 参数，非 default 时通过 `extra_body={"reasoning_effort": ...}` 下发（不支持的 Provider 会自行忽略，不影响现状）。
- `providers/base.py` `chat()` 透传 agent 的 effort；agents.json 旧数据无此字段时按 default 处理。

## 二、前端

### 5. `RecommendDialog.tsx`（新建，复用 ui.tsx 的 Modal + 深蓝暗色风格）
- 输入区：任务描述 textarea + 偏好 chips（成本优先/均衡/质量优先、要求响应快）。
- 结果卡片：首选模型（名称 + 厂商标签 + 推理档位徽章 + 置信度）+ 推荐理由；备选模型小表格；任务维度标签行；角标显示「LLM 推荐」或「规则匹配（离线）」。
- 若 `inWorkspace`：显示「应用到 Agent」行——选择目标 Agent 下拉 + 绑定按钮，调用 `api.updateAgent` 同时写入 binding 和 effort，成功后 `onChanged()` 触发 refreshConfig；未配置则显示提示文案。
- 「模型库」页签：只读列表展示知识库（模型 / 厂商 / 擅长 / 档位 / 成本 / 速度）。

### 6. 接线
- `api.ts` 加 `recommendModel()` / `selectorModels()`；`types.ts` 加对应接口。
- `TopBar.tsx` 右侧按钮组加「模型推荐」ghost 按钮（lucide Sparkles 图标），`App.tsx` 加 `showRecommend` 状态并渲染对话框。

### 7. 顺手修复现存的 4 个 `tsc --noEmit` 错误
`ui.tsx` 缺 type import、`EventStream.tsx` 两处 null 兼容——各一行改动，让 `npm run build` 恢复可用，也便于最终验证。
